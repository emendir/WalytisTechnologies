# Operating System Requirements

## Overview

The operating environment MUST provide the following:

- [the ability to execute the system implementation as a persistent process or service](#Process%20Lifetime%20and%20Restart)
- [access to persistent local storage and filesystem](#Filesystem)
- [a source of cryptographically secure random data](#Cryptographically%20Secure%20Randomness)
- [access to IP networking](2.%20Network.md)

Implementations SHOULD NOT depend on a particular operating system.

## Filesystem

##### Requirements

The operating environment MUST provide persistent storage with the following properties:

- Data remains available across normal process and system restarts.
- Files can be created, read, modified, and deleted as required by implementations.
- Filesystem permissions or equivalent access controls can be used to prevent unauthorised local processes from accessing data protected by implementations.

##### Limitations

It is not assumed that the filesystem provides [Strong Protection](../Security%20Model/6.%20Protection%20Levels.md#Strong%20Protection).

##### Implementation Notes

Implementations MUST account for unexpected process or system termination occurring during a write operation.

Implementations SHOULD NOT assume that deletion of a file makes its previous contents unrecoverable.

Implementations MUST NOT rely on filesystem timestamps as an authoritative source of time.

Implementations SHOULD, when packaged, make use of filesystem access controls to prevent other processes from accessing their storage.

## Persistent Storage Capacity

##### Requirements

The operating environment MUST provide sufficient persistent storage for the local state maintained by implementations.

##### Implementation Notes

Implementations SHOULD define which data may grow without a predetermined upper bound.

Implementations SHOULD implement mechanisms for detecting insufficient storage capacity and avoid increasing their own storage when this is detected.

Exhaustion of persistent storage MUST NOT result in corruption of previously committed identity state.

## Cryptographically Secure Randomness

##### Requirements

The operating environment MUST provide a cryptographically secure source of random data suitable for generating cryptographic keys, nonces, identifiers, and other security-sensitive values.

##### Implementation Notes

Implementations MUST NOT use an ordinary pseudo-random number generator as the sole source of security-sensitive randomness.

Implementations MUST detect or otherwise account for failure of the operating environment's secure random source.

## Clock

##### Limitations

It is assumed that the wall clocks of peers in a network are not synchronised.

##### Implementation Notes

Implementations MAY use the local clock for local purposes such as scheduling retries, expiring locally generated state, or presenting timestamps to users, provided that incorrect or manipulated local time does not violate the security guarantees of the protocol.

## Processing Resources

##### Requirements

The operating environment MUST provide sufficient CPU and memory for implementations to perform its required cryptographic, database, and networking operations.

##### Implementation Notes

The exact minimum CPU and memory requirements are implementation-dependent and MAY be specified separately.

Resource exhaustion MUST NOT cause implementations to violate its security properties.

In particular, an implementation MUST fail safely when insufficient memory, CPU time, storage capacity, or other local resources are available.

## Process Lifetime and Restart

##### Requirements

The operating environment MUST provide:
- the ability to execute the system implementation as a persistent process or service
- sufficient isolation to satisfy the [Strong Protection](../Security%20Model/6.%20Protection%20Levels.md#Strong%20Protection) requirements of the local execution environment

##### Implementation Notes

Implementations MUST tolerate unexpected termination and subsequent restart.

Persistent state MUST be sufficient to reconstruct the identity's state after restart without requiring uninterrupted execution.
