# Block Constituents — Definitions and Constraints

## Content

If the blockchain's configuration defines Maximum Content Length, the length of the block's content in bytes DOES NOT exceed the Maximum Content Length.

A Block's Content length measured in bytes count MUST be greater than zero, 

## Custom Metadata

If the blockchain's configuration defines Maximum Custom Metadata Length, the length of the block's custom metadata in bytes DOES NOT exceed the Maximum Custom Metadata Length.

A Block's Custom Metadata's length as measured in bytes count MAY be zero.

## Blockchain Configuration

A Genesis Block DOES contain a Blockchain Configuration payload.
A Post-Genesis block DOES NOT contain a Blockchain Configuration Payload.

The fields that Blockchain Configuration comprises are specified in [Blockchain Configuration](Blockchain%20Configuration.md#Blockchain%20Configuration).

## Genesis

In Genesis Blocks, the Genesis field IS `true`.

In Post-Genesis Blocks, the Genesis field IS `false`.

## Parent Identifiers

In Genesis Blocks, the list Parent Identifiers DOES NOT contain any elements.

In Post-Genesis-Blocks, the list Parent Identifiers DOES contain at least one element.

The list Parent Identifiers DOES NOT contain duplicate elements.

Parent Identifiers ARE sorted in ascending lexicographic order by their unsigned bytes, comparing the first differing byte and placing the shorter identifier first when one identifier is a prefix of another.

Each of the blocks referenced by the Parent Identifiers ARE validated blocks of the same blockchain instance.

The blocks referenced by the Parent Identifiers ARE Cousin Blocks.

If the blockchain's configuration defines Maximum Number of Parents, the Number of Parents DOES NOT exceed the Maximum Number of Parents.

## Content Length

The Content Length IS equal to the length of the block's content in bytes.

## Content Hash

The Content Hash IS the hash computed by the algorithm specified in Content Hash Algorithm from the Block Content.


## Number of Parents

Number of Parents IS equal to the number of elements in Parent Identifiers.

## Parents Hash

The Parents Hash IS the hash computed by the algorithm specified in Parents Hash Algorithm from the preimage composed of the concatenation of the following ordered elements:
- The concatenation of the length (byte count) of each element in the ordered list of Parent Identifiers, the lengths each being encoded as specified in [Integer Encoding](#Integer%20Encoding) and appended with a delimiter $255$.
- The concatenated elements of the ordered list Parent Identifiers

The ordering of the Parent Identifiers is specified in [Parent Identifiers](#Parent%20Identifiers).

## Block Hash

The Block Hash IS the hash computed by the algorithm specified in Block Hash Algorithm from the concatenation of block content, block metadata excepting fields derived from others, and in the case of Genesis blocks the Blockchain Configuration, encoded as follows:

The sequence of bytes (also called hash pre-image) IS composed by concatenation of the following ordered elements:

- Genesis (encoded as specified in [Boolean Encoding](#Boolean%20Encoding))
- only if Genesis is `true`, the Block Configuration (encoded as specified in [Blockchain Configuration Encoding](#Blockchain%20Configuration%20Encoding), followed by a delimiter $(255)$)
- Blockchain Version (encoded as specified in [Integer Encoding](#Integer%20Encoding), followed by a delimiter $(255)$)
- Content Hash Algorithm (encoded as specified in [Hash Algorithm Identifier Encoding](#Hash%20Algorithm%20Identifier%20Encoding), followed by a delimiter $(255)$)
- Parents Hash Algorithm (encoded as specified in [Hash Algorithm Identifier Encoding](#Hash%20Algorithm%20Identifier%20Encoding), followed by a delimiter $(255)$)
- Block Hash Algorithm (encoded as specified in [Hash Algorithm Identifier Encoding](#Hash%20Algorithm%20Identifier%20Encoding), followed by a delimiter $(255)$)
- the hash preimage specified in [Parents Hash](#Parents%20Hash)
- Content Length (encoded as specified in [Integer Encoding](#Integer%20Encoding), followed by a delimiter $(255)$)
- Content
- Custom Metadata

## Block Identifier

A Block's Identifier IS a sequence of bytes that directly encodes via aggregation all a block's metadata except for its parents' identifiers.

A Block Identifier permits reconstruction of the metadata fields it directly encodes.
Parent Identifiers, Block Content, and Blockchain Configuration cannot be reconstructed from the identifier alone, but can be verified via the hashes that are directly encoded.

Walytis uses a custom algorithm for encoding a Block's metadata into its identifier optimised for size while retaining protocol expansibility.
The sequence of bytes IS composed by concatenation of the following ordered elements:

- Genesis (encoded to a fixed-length byte sequence as specified in [Boolean Encoding](#Boolean%20Encoding))
- Blockchain Version (encoded as specified in [Integer Encoding](#Integer%20Encoding), followed by a delimiter $(255)$)
- Content Length (encoded as specified in [Integer Encoding](#Integer%20Encoding), followed by a delimiter $(255)$)
- Content Hash Algorithm (encoded as specified in [Hash Algorithm Identifier Encoding](#Hash%20Algorithm%20Identifier%20Encoding), followed by a delimiter $(255)$)
- Content Hash (bytes sequence as-is, sequence length is derived from Hash Algorithm)
- Number of Parents (encoded as specified in [Integer Encoding](#Integer%20Encoding), followed by a delimiter $(255)$)
- Parents Hash Algorithm (encoded as specified in [Hash Algorithm Identifier Encoding](#Hash%20Algorithm%20Identifier%20Encoding), followed by a delimiter $(255)$)
- Parents Hash (bytes sequence as-is, sequence length is derived from Hash Algorithm)
- Block Hash Algorithm (encoded as specified in [Hash Algorithm Identifier Encoding](#Hash%20Algorithm%20Identifier%20Encoding), followed by a delimiter $(255)$)
- Block Hash (bytes sequence as-is, sequence length is derived from Hash Algorithm)
- Custom Metadata (bytes sequence as-is, trailing)

When decoding metadata from an identifier, the elements described above are decoded sequentially using the byte sequence lengths determined as described above for each element.

A Block Identifier MUST be rejected if any field is malformed, any hash algorithm code is unknown, any fixed-length hash field is truncated, any integer encoding is non-canonical, or any required delimiter is missing.

Decoding MUST consume all bytes, with the remaining bytes assigned exclusively to Custom Metadata.

Decoding a Block Identifier IS NOT full Block validation.

### Encodings

#### Integer Encoding

A non-negative integer IS encoded using its canonical base-255 representation, in order of descending order of magnitudes.

The result for positive integers MUST NOT contain leading zeroes.
The integer zero is encoded as $(0)$.

To decode an integer, the sequence of bytes are interpreted as base-255 digits in order of descending order of magnitudes.

An empty digit sequence MUST be rejected.
A digit sequence containing values outside the range $[0,254]$ MUST be rejected.

For example:

$$
i = 1234
\newline
r = ( 4, 214 )
$$
Where:
- $i$ is the integer value
- $r$ is the sequence of digits that comprise the result in bytes

The encoded integers are byte sequences where each byte $∈[0,254]$.
This encoding is designed to be used with the delimiter $(255)$.

### Hash Algorithm Identifier Encoding

The following table matches algorithm identifiers with their byte-sequence codes, as well as specifying the length of hashes associated with them:

| Hash Algorithm Identifier | Code (Byte Sequence) | Hash Length (bytes) |
| ------------------------- | -------------------- | ------------------- |
| SHA-512                   | (0)                  | 64                  |
| SHA3-512                  | (1)                  | 64                  |

Future extensions of this specification WILL set codes that are byte sequences where each byte $∈[0,254]$.

These codes are designed to be appended with the delimiter $(255)$.


### Boolean Encoding

If the value is `true`, the result is $(1)$.
If the value is `false`, the result is $(0)$.

$$
r(b) =
\begin{cases}
(1) & \text{if } b \text{ is true},\\
(0) & \text{if } b \text{ is false}.
\end{cases}
$$

Where:
- $b$ is the boolean being encoded
- $r$ is the resulting sequence of bytes.

### Blockchain Configuration Encoding

The Blockchain Configuration encodes the following ordered list of nullable integers:
- Maximum Content Length
- Maximum Custom Metadata Length
- Maximum Number of Parents

Blockchain Configuration is encoded by representing each item as an empty byte sequence if null, otherwise through its value encoded as specified in [Integer Encoding](#Integer%20Encoding).
These items are concatenated, separated by a delimiter $(255)$.

The encoded Blockchain Configuration is decoded by splitting it at the delimiters $(255)$ into multiple elements, preserving empty sequences between delimiters and before the first and after the last delimiter.
Each element is decoded as a null value if it is an empty sequence of bytes, otherwise it is decoded into an integer as specified in [Integer Encoding](#Integer%20Encoding).
The resulting list of nullable integers is assigned to fields of Blockchain Configuration according to the order specified above.

When decoding, inputs containing any number of delimiters other than one less than the number of elements defined above MUST be rejected.
