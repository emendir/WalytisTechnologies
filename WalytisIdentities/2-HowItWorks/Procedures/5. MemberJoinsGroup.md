### Objects

- `GroupDidManager` $G$
- `DidManager` $A$ is already a member of $G$
- `DidManager` $B$ is not yet a member of $G$

### Process

- $A$ creates an `Invitation` $I$, which is transmitted out-of-band by the user to the device running $B$, consisting of:
	- a newly generated asymmetric encryption key ${K}_{I}$'s public part
	- the public IPFS multiaddresses of $A$
- $B$ decodes the blockchain data from the `Invitation` $I$ and joins the blockchain.
- $B$ creates an ephemeral asymmetric encryption key ${K}_{b}$ solely for the following communications session.
- $B$ starts a `JoinRequest` communications session:
    - $B \rightarrow A$: In the session handshake initiation message, it encodes:
        - **public key**: the public key of ${K}_{B}$
        - **challenge**: a newly generated random string for an authentication challenge
    - In all following steps, transmissions from $A$ to $B$ will be encrypted with ${K}_{b}$
    - $A \rightarrow B$: In the session handshake response message, $A$ encodes:
	    - **public key**: the public key of $G$'s control key ${K}_{G}$
	    - **authenticity proof**: a signature on $B$'s challenge by ${K}_{I}$
    - In all following steps, transmissions from $B$ to $A$ will be encrypted with the public key ${K}_{G}$
	- $B$ verifies $A$'s authenticity proof to ensure it is really communicating with the author of `Invitation` $I$.
	- $B \rightarrow A$ : $B$ sends the message "Ready!"
	- $A \rightarrow B$: $A$ sends a message containing:
		- **control keys**: the full private keys of $G$
		- **blockchain ID**: the blockchain ID of $G$
	- $A \rightarrow B$: $A$ sends a file containing $G$'s blockchain's appdata.
- $B$ loads the blockchain from the appdata file.
- $B$ loads the `GroupDidManager` $G$ using the blockchain and private keys.
- $B$ ensures the private keys match the current control keys listed on the blockchain.
- $B$ adds a `MemberJoining` block on the blockchain, encoding $B$'s ID.
- $B$ updates $G$'s `DidDocument`, containing an updated list of all of $G$'s members.

## Notes

- Note that $A$ doesn't generate a temporary encryption key for the joining session, using the `GroupDidManager`'s control key instead. This is deemed sufficiently secure because the only data encrypted with it in this session is $B$'s message "Ready!". This has the advantage of slightly improved performance, sparing the generation of a new temporary set of encryption keys.
